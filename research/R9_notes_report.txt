    Verdict for comparison: plain chatbots are clearly BELOW the 10k floor;

    A2. Coding agents (Claude Code / Cursor / Codex class)
    These layer a large fixed system prompt + an explicit tool/schema corpus

    - Point estimate: ~30-40k typical mid-task [MED] [anecdote]

    Our own measured "paperwork" alone: 97.7KB = ~33k tokens re-sent on EVERY
    call [given, take as fact]. So the fixed overhead of a real code agent

    A3. Long-running autonomous agents
    Context only grows: each hop appends tool inputs/outputs and the running
    transcript; nothing meaningful is dropped unless compaction/editing runs.
    So per-call re-sent size is monotone-ish over a run.
    - Range: early calls maybe 20-40k, mid-run typically 40-120k, late-run
    higher [LOW-MED] [anecdote]
    - Point estimate: ~50-80k at mid-run for a multi-hour multitool run
    without manual compaction [LOW-MED] [anecdote]
    - Caveat: agents that auto-compact (Claude Code /compact, OpenAI
    summaries) hold it flatter; agents that don't, grow unbounded [MED]
    [vendor doc].

    B1. Delivery paths for our auditor/complementary lane (NO proxy, by

    (1) Read-only store-census CLI printing a personal dollar card.

      - Install friction: medium (must hook the assembly layer, not just read).
      - Invasiveness: medium-high (it edits what is sent).
      - Per-user verifiable: YES (token before/after + cache-hit delta).
      - Complement: yes, and this is the R8 "cache-optimizer first" lever
    [from our own R-series, treat as given].
    (3) Post-hoc store sweep with quarantine (reversible, opt-in).
      - Install friction: low-medium.
      - Invasiveness: medium (touches stored history) but reversible +
    opt-in, matches our existing file-delete quarantine pattern.
      - Verifiable: YES (token deltas from the sweep).
      - Complement: yes (compressors work on live traffic; we clean stored

    (4) Framework integration (LangChain callback, OpenAI SDK wrapper, Claude
    Code hooks).
      - Install friction: high (one adapter per framework, version churn).
      - Invasiveness: highest per framework at the call layer.

      - Complement: weaker, edges toward the proxy lane and competes for

    (5) Stronger alternatives: the cache-optimizer middle layer
    (reassemble/order context to maximize prefix cache hits) done client-side

    Both preserve no-proxy constraint, keep measurement + optimization on the

    Ship path (1), the read-only store-census CLI dollar card, as the first
