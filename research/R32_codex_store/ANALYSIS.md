## Session file census (172,360 B, 118 lines)

Record types: `event_msg` 60 (57K), `response_item` 37 (49K), `token_usage_record` 13 (11K), `turn_context` 6 (24K), `session_meta` 1 (23K), `world_state` 1 (8K).

1. **Content density: 24%.** Actual conversation (messages + tool calls + tool outputs) = 42,132 B of 172,360 B.
2. **Static context re-dump: 27%.** 6 `turn_context` records of 4,124 B each. First vs last differ in exactly 2 fields (`turn_id`, `root_turn_id`); constant part ~3,696 B x 6 = ~22.2 KB, of which ~18.5 KB is delta-encodable.
3. **Byte-identical duplication EXISTS (unlike Claude Code).** A 1,288 B "Collaboration Mode: Default" boilerplate block appears in 13 records: 6x `turn_context`, 6x `event_msg/thread_settings_applied`, 1x first `response_item/message` (12 exact full copies). Waste from exact string dupes: 16.3 KB = 9.5% of the file.
4. **Dual-stream mirroring.** `response_item` and `event_msg` streams describe the same events in different envelopes (37 vs 60 records; 0 byte-identical overlaps at full-record level). Same dual-envelope disease class as Claude Code, tamer.
5. **Reasoning is SEALED.** 3 reasoning records, `summary=[]`, `encrypted_content` 1,892-2,040 B each (5,844 B total, `gAAAAA` Fernet-style prefix). GPT's thinking never touches disk as readable text. Unverifiable content, unauditable without OpenAI keys.
6. **Token receipts x2.** 13 `token_usage_record` + 13 `event_msg/token_count` - same receipt class as Claude's `usage`, mirrored across streams.

## Cross-vendor verdict (n=1 per vendor, method-matched)

| | Hermes | Claude Code | Codex CLI |
|---|---|---|---|
| Session store weight | 206 MB (months) | 1.8 MB (project transcripts) | 0.2 MB (one session) |
| Content density | low | 27% | **24%** |
| Byte-identical dupes | yes, conversation data, proven removable 15%+ | **zero** (0/347 messages) | **yes**: boilerplate 9.5% + config 11% delta-encodable |
| Fat location | inside sessions | inside session scaffolding | **outside sessions** (program + caches ~390 MB) |
| Thinking on disk | plaintext, stored twice | empty + signature (never plaintext) | **encrypted blob (Fernet-style)** |
| Auditability | full | full | **none** (sealed reasoning) |

Three architectures, three diseases:
- Hermes: **redundant memory** - your data stored twice, provably curable.
- Claude Code: **scattered reshapes** - same data in multiple envelopes, no exact dupes, ~5-15% recoverable (estimate).
- Codex: **lean sessions, fat disk, sealed mind** - session records are the leanest and most transparent of the three, the program dumps ~390 MB around them, and reasoning is encrypted, so the store cannot be fully audited.

The thesis "you can't know what's inside your store until you weigh it" now has three independent proofs with three distinct failure modes.

## Honest limits

- n=1 session, one small lab, one model (`GPT-6.1-Sol`), one CLI version (0.163.0). No claims about long-session behavior.
- Encrypted reasoning blobs could not be inspected; "sealed" means "unreadable to us", not proof of hidden size.
- The 9.5% exact-dup waste is proven removable; the ~11% config delta-encoding is an engineering estimate (delta-encodable bytes, not a tested removal).
- Cost math omitted: no verified price data for the model used.
- User's original store untouched; census ran on a copy; `auth.json` never transferred.
