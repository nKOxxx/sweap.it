    AGENT MEMORY / OS-MEMORY SYSTEMS
    
    MemGPT, now Letta [high]. "Towards LLMs as Operating Systems" (arXiv
    2310.08560, 2023). Virtual context management: a fixed main context paged
    against an external storage tier; the model self-edits memory and
    triggers page-in/page-out. It already frames context as a scarce, priced
    resource and does byte/page accounting, which is the closest conceptual
    cousin to sweap.it's "re-payment" law. What it does NOT do: it does not
    measure the fixed per-call overhead (system prompt, tool schemas), does
    not compute tool-exhaust share of stored transcripts, and offers no
    dry-run or quarantine gated cleanup of session stores. It manages live
    memory, not reclaimable stored waste.
    
    Mem0 [high]. Two-phase memory pipeline: extraction (find relevant fact)
    then update (add/delete/conflict resolution), stored in vector+graph
    stores with short/long/memory types. Popular OSS agent-memory layer. Does
    NOT do byte-level accounting of what each memory costs per API call, has
    no dry-run "what would this reclaim" mode, and does not touch the host
    plane (session DBs, logs, scratch). It is a memory backend, not a sweeper.
    
    Zep / Graphiti (temporal knowledge graph memory) [high]. Bi-temporal
    graph memory with epi-cyclic fact invalidation; entities and edges get
    added, updated and invalidated over time. Notably it already has real
    deletion semantics inside an agent-memory model (invalidating stale facts
    for correctness). Does NOT frame deletion as byte reclamation, does NOT
    measure token cost of retained memory, no quarantine, no reclaim
    accounting. Deletion is for factual freshness, not hygiene.
    
    Letta Agent Developer Workstation (ADW) [high]. Data-persistence
    architecture and self-editing memory blocks on top of MemGPT. Context
    management and persistence, not disk/transcript hygiene or measurement of waste.
    
    CONTEXT-WINDOW MANAGERS AND SESSION COMPACTION (built into CLIs/frameworks)
    
    Claude Code /compact and auto-compact [high]. Compact summarizes the
    conversation to fit the context budget and writes ongoing knowledge to a
    CLAUDE.md-style file. This is the most mainstream "session hygiene"
    feature. What it does NOT do: the summarization is unmeasured (no report
    of KB reclaimed, no tool-schema or tool-share accounting), it is lossy by
    construction (information-loss risk, see section 2), it acts only on the
    active session, and there is no dry-run/quarantine gated "delete this and
    prove you reclaimed it" mode. It is also proprietary and not a
    measurement instrument.
    
    OpenAI Assistants / Responses API truncation [high]. When
    max_prompt_tokens is hit, the service truncates or (with a summary flag)
    summarizes the prior message list. Cleanup by token cutoff, lossy, opaque
    about what is dropped, no measurement, no gated reclaim. Direct ancestor
    of "the API decides what to forget".
    
    LangChain / LangGraph conversational memory [high].
    ConversationSummaryMemory, ConversationSummaryBufferMemory, and the
    LangGraph summarization node compress or drop message history. Same shape
    as above: summarization-based reduction, no measurement of waste
    composition, no dry-run or quarantine.
    
    AutoGen / AG2 chat summarization [med]. Group-chat history summarization
    and truncation. Same profile.
    
    MCP "memory" servers [med]. A family of Model Context Protocol servers
    exposing knowledge-graph or key-value memory for agents. They store and
    retrieve; none I know measures per-call cost, none does gated cleanup of
    the store.
    
    Context7 (Cloudflare MCP provider) [high]. Context engineering sold as a
    product: it curates which documentation/code context gets injected into
    the model, with caching and token budgeting. It manages what context
    enters, not what to remove or reclaim. Good FOIL for sweap.it: Context7
    is additive curation upstream, sweap.it is subtractive hygiene downstream.

    2. RESEARCH LITERATURE
    ========================================================================
    
    CONTEXT ENGINEERING
    
    Context engineering as a named discipline emerged from practitioner
    canon, most canonically Eugene Yan, Bryan Bischof, Charles Frye, Hamel
    Husain, Jason Liu, Shanko (2025, blog series "Context Engineering for AI
    Agents") [high]. The term itself predates LLMs (classic NLP "context
    engineering" for feature/context selection [med]). arXiv now hosts a thin
    "Context Engineering 2.0" follow-up (2510.26493, 2026) [med confidence on
    significance; the entry exists]. No single canonical arXiv survey yet;
    the field is mostly blogware. This is exactly the body of work sweap.it
    should cite as the framing lineage: context as a first-class, engineered
    resource.
    
    LONG-CONTEXT DEGRADATION AND CONTEXT ROT/DECAY
    
    Lost in the Middle (Liu et al., arXiv 2307.03172, 2023) [high]: models
    degrade on information placed mid-context regardless of total length;
    foundational for "long context is not free".
    InfinityBench (Zhang et al., arXiv 2402.13718, 2024) [high]: long-context
    eval beyond 100K tokens, shows recall collapse and positional effects,
    used to argue "context window capability is oversold".
    RULER (Hsieh et al., arXiv 2404.06654, 2024) [high]: shows real usable
    context is far below the advertised window once you inject
    distracting/noise tokens. Directly supports the claim that stuffing the
    window is wasteful and that hygiene matters. The needle-in-a-haystack
    benchmark (Kamradt, 2023) [high] is the practitioner precursor.
    I did not verify a specific peer-reviewed paper that literally names
    "context rot" or "context decay" as a term; this looks like
    blog/conference vocabulary. Flagged [med]: the phenomenon (degradation as
    context ages and competitors accumulate) is real and documented via
    ∞Bench/RULER and multi-session studies, but the exact coinage is not
    something I can pin to a stable citation. Do not cite a specific rot
    paper without verifying it yourself.
    
    COMPACTION / SUMMARIZATION OF AGENT HISTORY AND FAILURE MODES
    
    LLMLingua (Jiang et al., arXiv 2310.05736, 2023) [high]: prompt
    compression via a small LM to drop redundant tokens. Lossy.
    Compressing Context to Enhance Inference Efficiency of Large Language
    Models (Liu et al., arXiv 2310.06201, 2023) [high]: early
    lossy-compression survey; argues compression causes "lost in the
    middle"-style degradation. Good base for the information-loss failure
    mode.
    LLMLingua-2 (Pan et al., ACL 2024) [high on existence, year 2024]:
    task-agnostic, token-classification-based compression; confirms the lossy
    trade-off is a design axis, not a free lunch.
    Failure modes the literature consistently reports: amnesia (the model no
    longer recalls what was compacted), silent information loss (compression
    drops the fact, no error raised), and summarization drift (the summary
    diverges from the source over repeated passes). The amnesia class is well
    established in the memory-agent and RAG literature (see MemoryBank below)
    and in practitioner reports of /compact losing key instructions [med].
    Running a cleanup subject to this failure mode without a reversibility
    mechanism is the core safety argument sweap.it makes, and it is well
    grounded in this literature.
    
    MEMORY ARCHITECTURES FOR LLM AGENTS
    
    MemGPT / LLMs as Operating Systems (Packer et al., arXiv 2310.08560,
    2023) [high]: OS analogy, virtual memory, paging; the natural cite for
    "context as memory with a GC story".
    Generative Agents (Park et al., arXiv 2304.03442, 2023) [high]: memory
    stream with recency/importance/relevance retrieval; the template every
    retrieval-memory agent copies.
    Cognitive Architectures for Language Agents (CoALA, Sumers et al., arXiv
    2309.02427, 2023) [high]: consults/uses/updates memory taxonomy; the
    formal frame for what "memory" means in agents.
    A Survey on the Memory Mechanism of LLM-based Agents (Zhang et al., arXiv
    2404.13501, 2024) [high]: taxonomizes sensory/short/long memory; the
    survey to cite for the whole field.
    MemoryBank (Zhong et al., arXiv 2305.10250, 2023) [high]: long-term
    memory accumulation with a summarization-forgetting mechanism; explicit
    "forgetting" handling, relevant to safe-deletion semantics.
    ContextPipe: Database-Inspired Context Assembly for Long-Horizon Agents
    (arXiv 2609.00749, 2026) [high]: recent work framing context assembly
    with database-style discipline (e.g. pagination, eviction). Evidence the
    "context as a managed, evictable store" angle is live and well-trodden;
    must be cited and distinguished.
    
    TOKEN-COST ECONOMICS OF SYSTEM PROMPTS AND TOOL SCHEMAS
    
    The Prompt Report (Schulhoff et al., arXiv 2406.06608, 2024) [high]:
    systematic prompting-technique survey; background, not cost.
    The cost of large tool/function schemas and system prompts is mostly
    documented in practitioner reports and vendor pricing discussions, not
    peer-reviewed papers [med]. The closest literature anchors are
    tool-learning work such as Gorilla (Patil et al., 2023) [high], which
    shows models front-load massive API/tool surface, and the general
    observation that function-calling schemas dominate prompt overhead in
    agentic stacks. There is no canonical peer-reviewed paper measuring "X KB
    of tool schemas paid per API call" across tool counts; that is genuinely
    under-published, which the paper's day-0 census (28.7 KB system prompt,
    54.3 KB tool schemas for 28 tools, 85.4% tool-exhaust transcript share)
    would partially fill.
    
    ========================================================================
    3. INHERITABLE OLDER FIELDS
    ========================================================================
    
    GARBAGE COLLECTION THEORY
    Mark-sweep (McCarthy, 1960) [high] and Cheney semi-space copying [high]
    established the core operation: identify unreachable objects, collect
    them, and never touch reachable ones. The critical law that transfers:
    safe collection requires a precise reachability definition, and reachable
    (live) state is a hard-deny set. Sweep but never sweep the roots.
    Generational GC: the tenuring/generational hypothesis (Ungar, 1984; Ungar
    and Jackson, "Tenuring Policies for Generation-Based Storage
    Reclamation", 1988) [high] says most objects die young. This maps
    directly onto the context plane: most transcript bytes are recent tool
    exhaust that is dead on arrival, while a small core (skills, memory,
    identity) is long-lived and must be tenured/never collected. "Young data
    dies fast, tenured data is sacred" is the single most transferable law.
    
    LOG MANAGEMENT AND RETENTION POLICY
    logrotate, syslog-ng, journald [high]: rotation by size/time, compression
    of old logs, and a retention window with an explicit delete edge.
    SIEM/logging platforms (Papertrail, Datadog, Splunk) [high]:
    hot/warm/cold tiers plus compliance retention. Laws: (1) separate hot
    from cold explicitly; (2) retention policy is a declared, audited policy,
    not an ad hoc rm; (3) compression before deletion buys time; (4)
    append-only logs are for audit and are NOT swept by the same rules as
    scratch. The LLM-stack counterpart: an auditable manifest that says what
    is swept, why, and what was reclaimed, so cleanup is policy, not
    vandalism.
    
    STORAGE DEDUPLICATION
    LBFS (Muthitacharoen et al., 2001) [high] and rsync delta encoding [high]
    established content-defined chunking and reuse detection. Law: the most
    reused bytes (system prompt, tool schemas repeated every call) are the
    highest-value dedup/compression targets, and identical shared prefixes
    are the cheapest to elide. Dedup is the inverse framing of sweap.it:
    where sweep removes, dedup elides, and both run on the observation that
    most stored bytes are identical or dead.
    
    DISK-CLEANER PRODUCT HISTORY (TRUST AND DISTRUST)
    The lineage that shapes user expectations: Norton/Symantec utilities and
    Disk Cleanup (system, reversible-ish) [high]; CCleaner (once the beloved
    "safe" cleaner, then a 2017 supply-chain compromise via its parent, plus
    bundling/bloatware and telemetry that destroyed trust) [high]; CleanMyMac
    (commercial, opaque, subscription pressure) [high]; BleachBit (open
    source, explicit about what it deletes, reversible by deletion to trash
    wherever possible) [high]. Laws that made cleaners trusted or distrusted:
    (1) reversibility and preview ("show me what you will delete") is the
    trust core; (2) transparency/provenance of the binary and the action
    builds trust; (3) silent destructive defaults, bundled crapware, and
    phoning-home telemetry destroy trust overnight; (4) an auditable reclaim
    report is credibility. sweap.it's "default to reversible, dry-run by
    default, quarantine before delete, inventory never lies" is precisely the
    trust architecture the trusted cleaners had and CCleaner lost.

    WHAT NO ONE MEASURES OR SELLS (the claimed gap)
    1. No product measures fixed per-call overhead broken down into system
    prompt bytes plus tool-schema bytes ranked per tool, and prices it per
    API call. Context7 manages what enters, cost dashboards report spend, but
    none does this composition audit of fixed overhead. This is measured
    nowhere I could verify.
    2. No product reports tool-exhaust share of stored transcript bytes (the
    85.4% headline) as a reclaimable waste composition metric.
    3. No product gate cleans conversation state behind dry-run plus
    quarantine with a measured, itemized reclaim report and a hard-deny list
    of roots (skills, memory, active session).
    4. No product unifies the two planes (durable host waste and transient
    context waste) in one manifest with one pricing lens (re-payment on every
    call). Vendors operate on one plane only.
    
    WHERE sweap.it IS NOVEL (be brutal about the reverse)
    The two-plane frame with a single per-call price lens is a genuine
    synthesis I cannot attribute to anyone. "Default to reversible" applied
    to conversation state in production agent tooling, as a deliberate
    inversion of the CLI convention, is not something I can point to in any
    shipped product. Treating stored session state as durable, reclaimable
    bytes with safe-deletion semantics, as opposed to lossy summarization, is
    a real reframing: everyone compacts, nobody
    deletes-with-quarantine-plus-proof.
    
    WHERE sweap.it IS NOT NOVEL (be equally brutal)
    1. Every component is individually prior art: OS-memory management
    (MemGPT), agent memory (Mem0/Zep/CoALA), session compaction (Claude Code,
    LangChain, OpenAI truncation), host disk cleaning (CCleaner/BleachBit),
    retention policy (logrotate/logging platforms), dry-run flags (rsync -n,
    mutagen dry-run, every safe backup tool), dedup (LBFS/rsync), garbage
    collection (mark-sweep/generational). Nothing about sweeping, gating, or
    measuring is new in the abstract.
    2. Dry-run + reversible is textbook backup-software convention; claiming
    it as invention would be a fatal overreach. The novelty is only in
    grafting it onto agent conversation state with a measured reclaim report.
    3. Summarization as hygiene is well covered by Claude Code and LangChain;
    the failure-mode warnings (amnesia, silent loss) are documented in the
    memory/compression literature. "Cleanup of context" as a category is not
    new.
    4. Deleting stale facts is done by Zep/Graphiti and MemoryBank; deletion
    semantics for agent memory is not new. Only byte-level, reversible,
    measured cleanup of the host store is.
    
    ========================================================================
    5. THE TEN SHARPEST ATTACK QUESTIONS
    ========================================================================
    1. MemGPT/Letta could claim "context as a priced resource with byte
    accounting and self-editing memory" (arXiv 2310.08560). Rebuttal: it
    manages live virtual memory, not measurable stored waste with dry-run
    reclaim; no per-call fixed-overhead accounting, no host plane.
    2. Claude Code /compact could claim session-hygiene cleanup via
    compaction, the most mainstream version of this feature. Rebuttal: lossy,
    unmeasured, single-plane, no quarantine or reclaim proof; it forgets
    silently rather than deletes reversibly.
    3. LangChain/LangGraph summarization nodes could claim transcript
    reduction is prior art. Rebuttal: reduction by summarization, not
    measurement plus gated reclamation; identical failure-mode exposure
    without reversibility.
    4. Disk-cleaner lineage (CCleaner/CleanMyMac/BleachBit) plus logrotate
    retention could claim the host plane wholesale. Rebuttal: none are
    LLM-aware, none compute the context plane or the re-payment cost, and
    their trust record is exactly the cautionary tale sweap.it cites.
    5. LLMLingua and the lossy-compression line (2310.05736, 2310.06201)
    could claim compaction/hygiene is prior art. Rebuttal: compression is
    lossy transformation, not safe deletion with information semantics;
    sweap.it's point is that gated reversible removal beats silent loss.
    6. rsync -n / mutagen dry-run and backup-software conventions could claim
    "default to reversible, dry-run first" outright. Rebuttal: trivially true
    and conceded (section 4); the novelty is the application to conversation
    state with a measured, auditable reclaim report, not the pattern itself.
    7. Tracing/observability platforms (LangSmith, Arize, OpenTelemetry)
    could claim "we already measure agent context and transcript spans".
    Rebuttal: they measure cost/performance/traces, not waste composition or
    reclaimable bytes, and they observe rather than act; no cleanup, no
    quarantine.
    8. The agent-memory field (CoALA 2309.02427, Memory survey 2404.13501,
    MemGPT) could claim "memory management is an established field".
    Rebuttal: management and hygiene are different; the taxonomy is about
    what to store and retrieve, not what to delete for byte reclaim with
    safety gating.
    9. Zep/Graphiti temporal deletions and MemoryBank forgetting could claim
    safe-deletion semantics for agent memory. Rebuttal: they delete for
    factual freshness/correctness within a temporal model, not for cost
    reclamation, and without dry-run gating or reclaim accounting.
    10. ContextPipe, database-inspired context assembly (2609.00749, 2026)
    could claim "context as a managed, evictable store" and thus the whole
    context-plane framing. Rebuttal: it assembles/evicts to keep the agent
    coherent for long horizons, not to measure and reclaim byte-level waste
    with an auditable two-plane manifest; still, this is the strongest recent
    prior-art pressure and must be addressed head-on in the paper.
    
    ========================================================================
    BOTTOM LINE FOR THE PAPER
    The defensible core is not sweeping, measuring, gating, or deleting
    alone, all are prior art. The defensible claims are: (1) the two-plane
    unified manifest with a per-call re-payment cost lens, (2) the
    composition audit of fixed overhead and tool-exhaust share, which is
    under-published and un-shipped, and (3) reversible, quarantine-gated,
    measured reclamation applied to production conversation state, an
    application nobody has productized. Frame novelty as
    synthesis-and-application, concede every component, and pre-answer attack
    #6 and #10 in the paper. Also: re-verify the competitor sweep and the
    "context rot" coinage from a non-blocked network before submission, since
    both were flagged here as unverified.
