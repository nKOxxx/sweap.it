    RESEARCH LEAD BRIEF, WAVE R1b, sweap.it harvest triage and use-map
    
    1. MUST-READ TEN
    
    1. 2507.13334, A Survey of Context Engineering for LLMs (264 upvotes).
    The field map. We cite it as the canonical literature review and borrow
    its taxonomy to define sweapit layers in the paper.
    
    2. 2607.21503 (HF), Agentic Context Management: Solving Agent Memory and
    Cost by Treating Them as Lifecycle and Architecture Problems. Closest
    conceptual framing to sweapit: memory and cost as lifecycle. We adopt its
    lifecycle framing and explicitly differentiate the hygiene/cleanup plane
    it never builds.
    
    3. 2602.07398 AgentSys, Secure and Dynamic LLM Agents Through Explicit
    Hierarchical Memory Management. A hierarchy for host-plane versus
    context-plane separation, plus the security argument for why explicit
    cleanup beats implicit pruning. We borrow the hierarchy and the
    secure-deletion stance.
    
    4. LLM Token Estimation Benchmark Data (OpenAlex). A reuse-ready
    measurement baseline for our context-plane census and token accounting.
    No hand-rolling counts.
    
    5. An Independent Billing Audit of Claude's Production API (OpenAlex).
    Real vendor cost data with a reproducible method. We adopt the audit
    method, then invert it: nobody audits the stack locally, we measure local
    waste instead of vendor bills.
    
    6. Compression Remembers the Detour: How Context Compression Amplifies
    Off-Task Content and Derails LLMs (OpenAlex). Direct evidence that lossy
    compression makes things worse. This is our core motivating citation for
    distill-before-sweep preservation over naive compression.
    
    7. 2601.18642 FadeMem, Biologically-Inspired Forgetting. The closest
    theory of forgetting in the ledger. We borrow its retention-curve idea as
    the seed of our deletion semantics and preservation policy, then push it
    to real artifact deletion.
    
    8. 2604.13725, On the Effectiveness of Context Compression for
    Repository-Level Tasks. An empirical benchmark method for compression
    impact on real coding tasks. We reuse this as the backbone of our
    pre/post cleaning benchmark.
    
    9. 2608.04569, Referential Dangling as a Paradigm-Level Failure Mode in
    Hard Prompt Compression. Documents what breaks when you hard-compress.
    Motivates our provenance-preserving preservation store: we keep the
    referents, we never leave dangling refs.
    
    10. 2512.21567, Beyond Heuristics: A Decision-Theoretic Framework for
    Agent Memory Management. A principled decision model for when to act on
    memory. We borrow the decision-theoretic framing for our gated-cleanup
    layer, the approval loop nobody else formalizes.
    
    2. COMPETITOR MAP (GitHub section)
    
    (a) Monitors that measure but never clean: splitrail (223, highest in
    this class), aarora79/claude-code-usage-analyzer,
    SingggggYee/claude-usage-analyzer, CookiRui/claude-usage-analyzer,
    rennanbadaro/cursor-usage-analyzer, nathandavismail-cmyk/codex-run-audit,
    gega-dkv/agent-usage-stats. They read logs and report token/cost but have
    no cleanup path.
    
    (b) Single-CLI hacks: Watcher3056/llm-cleaner,
    vbiroshak/ai-dreamer-agent, jamiefutch/pi-hermes-memory-cleanup,
    hijrahassalam/llm-context-manager, khanak0509/ContextGc,
    kkdrhn/context-cleaner, MStock2025/mcp-context-cleaner,
    sdeture/claude-rolling-context, hijrahassalam. Each targets one engine or
    one job, no census, no preservation, no cross-tool view.
    
    (c) Memory systems without hygiene: matamong/memmd-mcp,
    physicspackage/mcp-memory-manager, SanDiegoAIStudio/mcp-context-manager,
    wabdull/Pane, arman81/context-manager, Gupta-Aniket/branched-llms,
    Dr-Vphuc/BranchChat. They persist and retrieve memory, some dedup, but
    none treat deletion as a first-class, reviewed, reversible act.
    
    (d) Genuine overlaps: blitzreels/blitzclean (234, the strongest star
    count in the whole GitHub set) and kylebrodeur/mac-optimize. Both do
    local host-plane monitoring with reviewed cleanup for AI agents on macOS,
    including session backup and git-worktree audit.
    
    Closest threat: blitzclean (234 stars, native macOS, reviewed cleanup for
    AI agents). Exact differentiation: blitzclean is single-machine
    host-plane disk/cache cleanup, no context-plane census, no cross-tool
    transcript distillation, no preservation store, no benchmark. sweapit
    spans host-plane plus context-plane census plus distill-before-sweep
    preservation plus gated-cleanup UX plus cross-host aggregation, and it
    does not depend on the macOS menu-bar surface.
    
    3. DESIGN USE-MAP (ledger items per product layer)
    
    Host-plane sweep: blitzclean and mac-optimize as proven pattern and
    benchmark; EvolKV 2509.08315 and R-KV 2505.24133 and PolyKV 2604.24971
    for KV-cache reclaim; ContextCache task-aware lifecycle (OpenAlex); Jenga
    2503.18292 and eLLM 2506.15155 for elastic memory management; The Missing
    Memory Hierarchy: Demand Paging (OpenAlex) for paging cache discipline.
    
    Context-plane census: LLM Token Estimation Benchmark Data; splitrail,
    claude-usage-analyzer family, agent-usage-stats as measurement methods;
    The Efficiency Frontier (OpenAlex) and Token-Economics for Agentic AI

    allocation; the Independent Billing Audit for audit method.
    
    Transcript distillation: View-oriented Conversation Compiler for Agent
    Trace Analysis (OpenAlex); Agent Memory Distillation 2608.07169;

    alternative form; Referential Dangling for the failure mode to avoid.
    
    Preservation store: FadeMem 2601.18642; From Recall to Forgetting

    value-aware interactive analytics (OpenAlex); matamong/memmd-mcp as the

    Benchmarking (pre/post cleaning performance): 2604.13725 repository-level
    compression efficacy; LOCA-bench 2602.07962 controlled context growth;
    Mem2ActBench 2601.19935; MemoryRewardBench 2601.11969; From Recall to
    Forgetting; DUET 2605.08441; the Independent Billing Audit for cost-side
    metric.
    
    4. GAP LIST (what the lit does not cover, that sweapit owns)
    
    No cross-host census. Every memory and compression paper operates inside
    a single model or context window. Nobody aggregates a corpus of
    host-plane and context-plane waste across many machines, tools, and long
    sessions. sweapit owns the cross-host census.
    
    No deletion-semantics work. FadeMem and From Recall to Forgetting model
    forgetting, they do not formalize what delete means for real artifacts:
    provenance-preserving deletion, tombstoning, undoability, referential
    integrity on removal. sweapit owns deletion semantics.
    
    No distill-before-sweep preservation layer. The compression literature is
    lossy and, per Detour and Sleeping Agent, demonstrably harmful. Nobody
    sequences distill-first-then-archive with verification before the
    destructive sweep. sweapit owns that ordering as a safety contract.
    
    No gated-cleanup UX study. No work measures trust calibration, the
    false-positive cost of deleting user data, or the approval-loop
    interaction cost of reviewed cleanup. blitzclean has a prompt but no
    study. sweapit owns the gated-cleanup UX measurement.
    
    No tool-exhaust quantification. No paper quantifies the 85-percent
    reality that agent context is mostly tool output (code dumps, file reads,
    retries). The literature compresses the wrong layer because it never
    measures what is actually in the window. sweapit owns the tool-exhaust
    measurement.
    
    No accuracy of the retention decision. Experience-following (2505.16067)
    touches retention but nothing instruments what agents actually keep, what
    they discard, and what they wish they had kept. sweapit owns retention
    ground truth.
    
    5. BUILD ORDER (leverage over effort, next 5 moves)
    
    1. Context-plane census instrumentation. Highest leverage: every other
    layer consumes its output. Moderate effort: existing session formats are
    already parsed by splitrail and the usage analyzers. De-risked by LLM
    Token Estimation Benchmark Data and the usage-analyzer methods.
    
    2. Host-plane sweep for one engine family (Claude Code, Codex, Cursor
    local caches). High visible win, low effort: the pattern is proven by
    blitzclean and mac-optimize and the formats are known. De-risked by
    Jenga, eLLM, The Missing Memory Hierarchy.
    
    3. Distill-before-sweep transcript distillation on the flagship engine.
    De-risked by View-oriented Conversation Compiler, MemRefine, Agent Memory
    Distillation, and explicitly guarded by Compression Remembers the Detour
    so we build the safety ordering first.
    
    4. Preservation store with provenance and undo. De-risked by FadeMem,
    Beyond Heuristics, MemLens, Referential Dangling. This is the
    defensibility moat, so higher effort, keep after the sweep proves value.
