    2. INTERACTION HYPOTHESES
    
    
    H1 STORE-ROT IS INVARIANT TO WINDOW HYGIENE. [INFERRED]
    caveman changes what is SENT, jev changes what stays in the live window;
    neither
    writes Hermes transcripts into state.db, so sweap's reclaim universe
    (dead tool
    output rows) is a property of the store and stays ~unchanged under B and
    C. Falsifier:
    if an optimizer's client writes elided/compacted content into the
    persisted transcript,
    the exhaust share drops. For Claude Code, whether fast-jev-compaction
    rewrites the
    on-disk .jsonl transcript or only the live provider window is NOT
    established in the
    harvest [OPEN; verify from the plugin repo]. Evidence: run B and C,
    re-run census at
    end; if share stays ~90.69%, H1 holds.
    
    H2 WIRE AND WINDOW SAVINGS MULTIPLY, STORE SAVINGS ARE THE ONLY
    PERSISTENT ONES.
    [INFERRED, with a subadditivity caveat]
    They touch overlapping bytes on a given call (caveman re-encodes history
    jev already
    elided), so they are not strictly disjoint populations; first-order D ~=
    B*C minus
    overlap, because caveman has less redundancy to exploit on
    already-compacted content
    [INFERRED]. Store savings persist because only sweap touches state.db
    while the others
    are in-flight/window only [consistent with H1]. Evidence: arm D vs A/B/C
    raw tokens; if
    D ~= B, window savings are a subset of wire savings (redundant),
    falsifying multiply.
    
    H3 VERBATIM-KEEPERS CONVERGE. [FAIR; category observation, the individual
    claims are
    facts]
    caveman claims byte-exact recovery, jev keeps kept items verbatim +
    exact-recall
    markers, sweap proves byte-identical restore. The category converges on
    "compress or
    drop, never rewrite" because rewrite invites drift/dangling refs (per R1b
    lit). The law
    is falsifiable: any candidate must expose a byte-identical or
    exact-recall path. But
    caution: "byte-exact" means a different original for each tool (caveman
    compressed form,
    jev pre-filter original, sweap raw store row). That conflation is a real
    category bug.
    
    H4 CONTEXT MUTATION BREAKS PROVIDER CACHE AND RE-BILLS THE PREFIX.
    [highest value]
    Prefix caching keys on byte-identical prefixes. Our baseline lane sits at
    96.3%
    cache-hit (glm-4.6, billed_usage_census.txt) with a reconstructed $53.80
    lifetime
    cache-break tax when the prefix wobbles. If jev drops/elides mid-session,
    the next
    request encodes differently, the cached prefix misses, and the provider
    re-bills the
    whole prefix as uncached. Same risk for caveman if its compression is
    content-dependent
    per turn [INFERRED on the reverse mechanism; the 96.3% and $53.80 are

    untooled baseline]. Corollary: a tool that LOWERS tokens-sent can RAISE
    billed cost if
    it fires too often. Nobody public publishes this number. The sweap wire
    sampler is
    built to catch it: a compaction event aligned to a cache_read collapse in
    the following
    window.
    
    
    
    3. COMPOSITION EXPERIMENT (the core ask)
    
    
    QUESTION: do the three planes multiply, interfere, or prove redundant?
    
    FOUR ARMS on one host:
      A baseline (no optimizer)
      B caveman only (OSS proxy on the same host, no Cloud tier needed)
      C jev-style compaction only (our policy-replay replica)
      D both (proxy + compaction replica)
    
    TASK SUITE: ~20 seeded deterministic agentic tasks that require tool
    calls (so real
    tool output is generated) with an objective, held-out oracle per task
    (test passes,
    exact answer) [protocol law from R2: external verifier runs the
    before/after task set,
    not the agent under test]. Same 20 tasks, same seeds, identical session
    inputs per arm.
    
    SIX METRICS, each with a local receipt:
      1. tokens sent: wire-sampler ledger per arm (wire_ledger_<arm>.jsonl).
      2. billed cost: dollars from the same usage table the sampler diffs,
    stamped
         [measured]/[reconstructed]/[projected], never blended.
      3. task success: fraction passing the oracle, per-task log.
      4. cache-hit rate: cache_read/(uncached+cache_read) per arm vs the
    96.3% baseline.
      5. store bytes at end: sweap census on the arm's store (census json per
    arm).
      6. restore fidelity: sweap SHA-256 byte-identical restore; replica
    exact-recall
         (every dropped/elided item resolves byte-identically to a local
    original).
    
    HOW TO RUN CHEAPLY ON ONE HOST IN DAYS:
    - SERIALIZE arms on SEPARATE fresh stores (a mutated store would
    contaminate the next
      arm's baseline and end-state). Fresh identical state.db clone per arm.
    This is the
      #1 honesty control.
    - SAME provider and SAME model across all four arms (cache behavior is
    model-specific;
      mixing lanes confounds cache-hit). Use the cheap/free lane (DeepSeek
    free lane per
      house law) so billed cost is comparative and near-zero.
    - Bounded runs: ~20 seeded tasks per arm, enough measurable exhaust, no
    24/7 job.
    - DAYS: Day 1 build harness + replica + pre-registration; Day 2 arms A+B;
    Day 3 arms
      C+D; Day 4 measure all six metrics + write receipts. ~4 days total.

    tool_use/tool_result against the whole conversation, elide to notes, drop

    newest N verbatim, pin first message, never touch user/assistant prose;

    KEEPING IT HONEST:
    - Pre-register tasks, seeds, metrics, thresholds, accept/reject rules

    - Same tasks/seeds, fresh identical store per arm, same provider+model.

    - Save raw artifacts per arm (ledgers, census, task logs, rebuild

    INTERPRETATION PLAN:
    - D near A - (A-B) - (A-C) with small overlap penalty: savings roughly
    ADD.
    - D clearly below the additive prediction: genuine multiply [surprising].
    - D ~= B: window savings redundant with wire savings on history. [H2
    multiply falsified]
    - cache-hit in any arm far below A's 96.3%: the H4 tax is live; recompute
    NET cost in
      dollars, not raw tokens. This is the number nobody publishes.
    - store bytes ~equal across arms: H1 confirmed. Lower in C/D: that
    optimizer writes
      back to the store; H1 falsified.
    - restore fidelity failing in any arm: that tool's "verbatim" claim is
    hollow.
    
    
    
    4. FAILURE MODES NOBODY PUBLISHES (three running together)
    
    
    1. CACHE THRASH (H4, the big one): mutations from compaction or per-turn
    re-encoding
       break the prefix cache; combined tools can LOWER tokens-sent while
    RAISING billed
       cost. "Savings" framed as raw tokens mislead; dollars are the true
    unit, and nobody
       ships that attribution ledger.
    2. THREE-WAY CONSISTENCY: the provider sees caveman's encoded bytes, the
    window sees
       jev's filtered view, the store holds the agent's raw rows. Different
    encodings of
       "the same" conversation; a byte-exact store restore does not
    reconstruct what the
       provider saw. Recall breaks across reference frames.
    3. REFERENCE-FRAME CONFLATION: three different "originals" all called
    verbatim (see H3).
    4. SCORING-DRIFT LOOP: if the compaction judge is an LLM and caveman
    changes the exact
       text the judge reads, judge quality shifts; the optimizers do not
    compose because
       one changes the other's input distribution.
    5. SHARED-ROW DIVERGENCE: a tool_result jev drops as stale (window) is
    still a stored
       row sweap may classify differently (store); opposing verdicts on the
    same artifact.
    6. BLAME AMBIGUITY + LATENCY: three layers, cost regressions
    unattributable without a
       unified ledger; N layers of tooling add per-call latency.
    7. COLD-CACHE CASCADE: if warm-cache and compaction both fire, cache
    state is unstable;
       worst case every call pays full uncached price, negating all claimed
    savings.
    
    
    
    5. POSITIONING FOR SWEAP (5 sentences max)
    
    
    sweap is the auditor, not another optimizer: it measures the store plane,
    which is the
    only plane whose savings survive sessions, restarts, and restores. When
    the wire
    (caveman) and the window (jev) both mutate context, neither can tell you
    what still
    sits at rest and gets re-sent forever after; sweap can, with an exact
    exhaust share and
    a dollar card billed from the provider's own counters. Its per-call wire
    sampler is the
    neutral attribution ledger that says which optimizer actually saved you
    money NET of any
    cache break, so it is the honest referee the whole category is missing.
    Because it stays
    read-only until a human gates it, and restores byte-identically
    (SHA-256), the auditor
    guarantees no optimizer stack can strand you with unrecoverable context.
    Put sweap
    between the optimizer stack and the money: it is the receipt for what all
    of them cost
    you.
