1. COMPARISON TABLE (facts + explicit inference; one row per tool)
================================================================================
Columns: PLANE | MECHANISM | CLAIMS | PROVES | LICENSE | BUSINESS MODEL | FAILURE MODE

CAVEMAN (JuliusBrussee/caveman, 111,865 stars)
- PLANE: THE WIRE. What is SENT per call, compressed in flight before the provider.
- MECHANISM: in-flight proxy that compresses request bytes before they reach the
  provider. README (Oct) also sells "warm cache" (keeps provider prompt-cache warm
  across pauses), caveman browse (121 tokens vs 15,704 for a page), /caveman-compress
  for memory files.
- CLAIMS: 33.2% fewer input tokens; 0.46x cost; 18/18 evals; "byte-exact recovery".
  All self-reported in README/site. R12 notes a July third-party test challenged
  "saves 65%" in real sessions, which became the warm-cache roadmap.
- PROVES: self-reported metrics; some independent July benchmarking (per R12). The
  "byte-exact recovery" is claimed, not independently re-verified in this series.
- LICENSE: Apache-2.0 (verified via GitHub API per DECISIONS.md).
- BUSINESS MODEL: free OSS core + Cloud $300/mo + VPC + npm middleware + CLI binaries;
  family repos (cavegemma, cavekit, caveman-browse).
- FAILURE MODE: in-path rewrite can shift task behavior; content-dependent re-encoding
  per turn can break provider prefix caches (H4) and re-bill the prefix at full price
  [INFERRED mechanism]; only helps bytes SENT, leaves store rot untouched.

JEV (TypeSafe AI; typesafe.ai blog 2026-09-15; Diogo Almeida ex-OpenAI)
- PLANE: THE WINDOW. What stays in the LIVE context.
- MECHANISM: "System One" model = input unstructured state + typed question, output =
  typed decision (choice/score/boolean) with calibrated confidence; gives up free-text
  generation; trained with RLCD (RL for Calibrated Decisions). Ecosystem, two artifacts:
  fast-jev-compaction (Claude Code plugin, 7,652 stars): scores every tool_use/
  tool_result against the whole conversation, elides results to notes, DROPS stale ones,
  keeps the rest VERBATIM, pins first message + newest N, never touches user/assistant
  prose. jev-context-router (research prototype): two-stage Jev filtering of tool
  outputs BEFORE they enter context, local originals + exact-recall markers.
- CLAIMS: ~100x faster/cheaper than chat LLMs on decision tasks; "unable to hallucinate
  in the generation sense"; compaction policy as documented.
- PROVES: compaction plugin ships (stars). Router is research: "self-reported:
  conservative candidate failed a real-agent usefulness gate, nothing auto-enables."
  The ~100x claim is vendor-reported, early access. Not independently measured here.
- LICENSE: not stated in the harvest [OPEN - verify before reuse; do not assume Apache].
- BUSINESS MODEL: early access for the System One model; startup (TypeSafe AI); router
  currently research-only, nothing auto-enables.
- FAILURE MODE: lossy at the decision boundary (drop/elide); a mis-scored "stale" drop
  strands load-bearing context; gives up free-text generation (cannot do open-ended
  work itself); any window mutation can break the provider prefix cache (H4) [INFERRED];
  the real-agent usefulness gate already failed once (their own report).

SWEAP (ours, github.com/nKOxxx/sweap when public, Apache-2.0)
- PLANE: THE STORE. What persists AT REST and gets re-sent forever after.
- MECHANISM: read-only census of the agent store (exact exhaust share, dollar card);
  provably-dead-only sweep to quarantine with SHA-256 over all columns; byte-identical
  restore proven; wire sampler = 1-min snapshot-diff of the store's in-place usage
  counters, producing a per-call-window cache ledger WITHOUT a proxy (cli/
  sweap_wire_sampler.py).
- PROVES (all measured on our host): 90.69% of stored transcript tokens are tool
  exhaust (exact tokenizer count, sweap_census_out.json); 14,955 rows / 19.56 MB / 48%
  of file provably-dead; live store reclaimed 22.1 MB (measured); restore byte-identical
  (SHA-256 verified before and after); wire ledger reconstructs per-call cache hits.
- LICENSE: Apache-2.0.
- BUSINESS MODEL: none yet, by design (FIRST_90_DAYS R4: no monetization until
  measured demand + falsifiable metric strangers verified + a named real-world gap;
  earliest Day 60+). OSS, owned domains sweap.it + sweapit.com only.
- FAILURE MODE: single-host store focus; quarantine hold consumes storage; a wrong
  "provably dead" verdict can strand references (mitigated by quarantine-first +
  byte-restore); does nothing in-flight or mid-session (needs the others or stays
  rest-plane-only).

================================================================================
2. INTERACTION HYPOTHESES H1-H4
================================================================================
H1: STORE-ROT IS INVARIANT TO WINDOW HYGIENE. [INFERRED]
Arg: caveman changes what is SENT; jev changes what stays in the live window; neither
writes Hermes transcripts into .hermes/state.db. sweap's reclaim universe (dead tool
output rows) is computed from stored rows and is independent of what the provider saw
or what survived compaction. The 90.69% exhaust share is a property of the store, so it
should be ~unchanged under B and C.
Caveat that would falsify it: if an optimizer's client writes elided/compacted content
into the persisted transcript (instead of raw tool output), the store's composition
changes and the exhaust share drops. For Claude Code specifically: the session persists
as .jsonl transcript files; whether fast-jev-compaction rewrites THAT file or only the
live provider window is not established in the harvest [OPEN - verify from the plugin
repo before trusting H1 for the jev arm on Claude Code].
Evidence to settle: run arms B and C, re-run the sweap census at end; if exhaust share
stays ~90.69%, H1 holds; if it drops, that optimizer writes back to the store.

H2: WIRE AND WINDOW SAVINGS MULTIPLY, BUT STORE SAVINGS ARE THE ONLY PERSISTENT ONES.
[INFERRED, with subadditivity caveat]
Arg on "multiply": caveman compresses every request (system, schema, history, echoes);
jev shrinks only the tool_use/tool_result region of the window. They overlap: caveman
re-encodes history jev already elided, so the two savings are NOT strictly disjoint
populations. First-order model: D ~= B*C minus overlap because caveman's compression
ratio on déjà-compacted content is lower (less redundancy to exploit) [INFERRED].
Arg on "store persists": only sweap touches state.db; neither caveman nor jev persists
across sessions/backups, so store-plane savings are the only ones that survive restarts,
backups, and restores [consistent with H1].
Evidence to settle: arm D vs A/B/C raw tokens. If D < B and D < C and D is roughly
A - (A-B) - (A-C) with a small overlap penalty, multiply-thin holds; if D ~= B, the two
are redundant on the history population (window savings are a subset of wire savings).

H3: VERBATIM-KEEPERS CONVERGE. [FAIR; category observation, the individual claims are facts]
Arg: caveman claims byte-exact recovery, fast-jev-compaction keeps kept items verbatim
plus exact-recall markers, sweap proves byte-identical restore. The category is
converging on "compress or drop, never rewrite" because rewrite introduces drift risk
(referential dangling, per R1b literature: hard compression leaves dangling refs).
The shared law is a falsifiable claim: any candidate tool must expose a byte-identical
or exact-recall path. sweap's SHA-256 restore is the strongest variant because it is
measured-verifiable, not merely claimed.
Note on "byte-exact" being ambiguous: caveman's reference frame is ITS compressed form;
jev's is the pre-filter local original; sweap's is the raw store row. Three different
"originals". Conflating them is a real category bug (see #4).

H4: CONTEXT MUTATION BREAKS PROVIDER CACHE AND RE-BILLS THE PREFIX. [HIGHEST VALUE]
Arg: prefix caching keys on byte-identical prefixes. Our own lane shows the untooled
baseline at 96.3% cache-hit (glm-4.6, billed_usage_census.txt) and a reconstructed
$53.80 lifetime cache-break tax when the prefix wobbles. If jev drops/elides a tool
result mid-session, the subsequent request encodes differently and the cached prefix
no longer matches: the provider re-bills the whole prefix as uncached input. Same risk
for caveman if its per-turn compression is content-dependent rather than stable
[INFERRED on the reverse-mechanism; the 96.3% hit and $53.80 tax are measured on the
untooled baseline]. The uncomfortable corollary: a tool that LOWERS tokens-sent can
RAISE billed cost if it fires often enough. Nobody public publishes this number.
Sweap's wire sampler is purpose-built to detect it: snapshot-diff per window yields
cache_read vs uncached input, so a compaction event aligns to a cache_read collapse in
the following window.

3. COMPOSITION EXPERIMENT (THE CORE ASK)
================================================================================
QUESTION: do the three planes multiply, interfere, or prove redundant?

DESIGN: one task suite, four arms, one host, days not weeks.
  A = baseline (no optimizer)
  B = caveman only (OSS proxy on the same host; Cloud tier not needed for the test)
  C = jev-style compaction only (our policy-replay replica, see below)
  D = both (proxy + compaction replica)

TASK SUITE: a fixed, seeded agentic harness. ~20 deterministic tasks where the agent
must CALL TOOLS (so real tool output = the exhaust plane is generated) and where success
is objectively checkable (test passes, exact answer) via a pre-registered held-out
oracle [protocol law from R2: external verifier runs the before/after task set, not the
agent being measured]. Reuse the frozen-snapshot protocol and the benchmark lane idea
from R1b (LOCA-bench / MemoryRewardBench lineage) but as OUR seeded suite, not a
borrowed one, so every number is ours and receipts are reproducible. Same 20 tasks, same
random seeds, identical session inputs per arm.

METRICS (the six requested), each with a local receipt:
  1. tokens sent: wire-sampler ledger (uncached + cache_read + cache_write + output)
     per arm. Receipt: ~/.sweap/wire_ledger_<arm>.jsonl.
  2. billed cost: dollars from provider usage (same table the sampler diffs) with
     [reconstructed]/[projected]/[measured] stamps. Cost = uncached*price_unc +
     cache_read*price_read etc., from the configurable price table, never blended.
  3. task success: fraction of the 20 tasks passing the oracle. Receipt: per-task log.
  4. cache-hit rate: cache_read / (uncached + cache_read) per arm, from the ledger.
     Compare to the 96.3% untooled baseline.
  5. store bytes at end: sweap census on the arm's store. Receipt: census json per arm.
  6. restore fidelity: for sweap, SHA-256 byte-identical restore after sweep (proven
     mechanism). For the compaction replica, exact-recall: every dropped/elided item
     resolves byte-identically to a local original via the recall marker.

HOW TO RUN CHEAPLY ON ONE HOST IN DAYS:
- SERIALIZE arms on SEPARATE fresh stores. A store mutated in arm A would contaminate
  arm B's baseline and its end-state, so each arm starts from an identical fresh
  state.db clone and stays isolated. This is the single most important honesty control.
- SAME provider and SAME model across all four arms. Cache behavior is provider/model
  specific; mixing lanes makes cache-hit incomparable. Use the configured cheap lane
  (DeepSeek free lane per house law) so billed cost is comparative and near-zero.
- Bounded runs: ~20 seeded tasks per arm (each a bounded session), enough to generate
  measurable tool exhaust without a 24/7 job.
- DAYS SCHEDULE: Day 1 build harness + replica + pre-registration file; Day 2 arms A+B;
  Day 3 arms C+D; Day 4 measure all six metrics, write receipts, compare. ~4 days total.

JEV EARLY-ACCESS UNAVAILABLE -> POLICY-REPLAY (honest fallback):
- Reimplement the DOCUMENTED policy of fast-jev-compaction (which is public): score
  every tool_use/tool_result against the whole conversation; elide results to notes;
  drop stale; keep newest N verbatim; pin first message; never touch user/assistant
  prose. Score "staleness" with a cheap LLM judge.
- LABEL IT as "our replica of the documented policy", NEVER as the Jev product. We
  measure the POLICY, not the proprietary System One model. Caveat in results: the real
  Jev model may score differently; the experiment isolates the policy's effect, which
  is the thing fast-jev-compaction actually documents and ships.
- This keeps the comparison honest: same task, same seeds, our own replica code,
  receipts; no claim that we measured TypeSafe's proprietary model.

KEEPING IT HONEST (house receipts law, applied):
- PRE-REGISTER: task list, seeds, metric definitions, thresholds, and the accept/reject
  rules written to a file BEFORE any arm runs. No post-hoc goalpost moving.
- Same tasks and seeds per arm; fresh identical store per arm; same provider+model.
- Every number stamped: [measured] (tool output), [reconstructed], [projected], never
  blended. Falsifiable: a stranger can rerun each arm and check any number.
- Save raw artifacts per arm: wire ledgers, census json, task result logs, and the
  rebuilding manifests; plus a compaction-event log (timestamped drops/elides) to test
  H4 by aligning events to the ledger windows.
- Self-sweep paradox law (R2): the measurer runs the before/after oracle, not the agent
  under test; census on a copy at measure time where relevant.

INTERPRETATION PLAN (what each outcome means):
- D tokens < B and < C, and D near A - (A-B) - (A-C) with small overlap penalty:
  savings roughly ADD (weak multiply). 
- D tokens clearly LESS than the additive prediction: genuine multiply.  [surprising]
- D tokens ~= B tokens: window savings are REDUNDANT with wire savings on history.  [H2 falsified for multiply]
- cache-hit in any of B/C/D falling well below arm A's 96.3%: the hidden H4 tax is live;
  recompute NET cost from billed dollars, not raw tokens. This is the number nobody
  publishes and the main honest risk in the whole category.
- store bytes ~equal across all arms: H1 confirmed (store-rot invariant).
- store bytes lower in C/D: that optimizer writes back to the store; H1 falsified.
- restore fidelity fails in any arm: the category's "verbatim" claim is hollow there.

4. FAILURE MODES NOBODY PUBLISHES (when the three run together)
================================================================================
1. CACHE THRASH (H4, the big one): mutations from compaction or per-turn proxy re-encode
   break the provider prefix cache; combined tools can LOWER tokens-sent while RAISING
   billed cost. "Savings" claims framed as raw input tokens are misleading if the cache
   breaks: dollars are the true unit, and nobody ships that attribution ledger.
2. THREE-WAY CONSISTENCY / DOUBLE-WRITE DIVERGENCE: the provider sees caveman's encoded
   bytes, the window sees jev's filtered view, the store holds the agent's raw rows.
   The three operate on different encodings of "the same" conversation. A byte-exact
   restore from the store does not necessarily reconstruct what the provider saw or
   what a rerun would re-send. Recall breaks across reference frames.
3. REFERENCE-FRAME CONFLATION: caveman "byte-exact" = its compressed form; jev = the
   pre-filter original; sweap = the raw store row. Three different "originals". Buyers
   and benchmarks treat "verbatim" as one thing; it is three.
4. SCORING-DRIFT FEEDBACK LOOP: if the compaction judge is an LLM and caveman changes
   the exact text that judge reads, judge quality shifts; the optimizers do not compose
   because one changes the other's input distribution.
5. SHARED-ROW DIVERGENCE: a tool_result jev drops as "stale" (window) is still a stored
   row sweap may classify as live or dead (store); two tools can reach opposing verdicts
   on the same artifact, and neither knows about the other's plane.
6. BLAME AMBIGUITY: with three layers, a cost regression is unattributable without a
   unified ledger; response time balloons (N layers of tooling, each adding latency).
7. COLD-CACHE CASCADE: if warm-cache and compaction both fire, cache state is unstable;
   worst case every call pays full uncached price, negating all claimed savings.

================================================================================
5. POSITIONING FOR SWEAP (5 sentences max) - where the auditor sits
================================================================================
sweap is the auditor, not another optimizer: it measures the store plane, which is the
only plane whose savings survive sessions, restarts, and restores. When the wire
(caveman) and the window (jev) both mutate context, neither can tell you what still
sits at rest and gets re-sent forever after; sweap can, with an exact exhaust share and
a dollar card billed from the provider's own counters. Its per-call wire sampler is the
neutral attribution ledger that says which optimizer actually saved you money NET of any
cache break, so it is the honest referee the whole category is missing. Because it stays
read-only until a human gates it, and restores byte-identically (SHA-256), the auditor
guarantees no optimizer stack can strand you with unrecoverable context. Put sweap
between the optimizer stack and the money: it is the receipt for what all of them cost
you.
